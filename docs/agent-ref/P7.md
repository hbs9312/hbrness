# P7: Validation

```
# backend
backflow:validate-code   src/              → convention, layer, error, type, security + drift (§7-§11)
backflow:validate-api    specs/TS-*.md     → API vs TS contract (clean-room)
backflow:validate-tests                    → coverage check

# frontend
frontflow:validate-code  src/              → convention, reuse, token, type, a11y + drift (§7,§9,§10)
frontflow:validate-visual                  → Storybook visual QA checklist
frontflow:validate-a11y                    → WCAG check
```

Validation optimization rules:
- Default to running validators; if impact is unclear, do not skip.
- Backflow controller loops: keep `validate-code` + integration tests; run whole-contract `validate-api` once at Final Gate.
- Skip `validate-code` only for docs/reports/non-runtime metadata-only commit units. Run it for source, migration, DTO, route/controller, service, repository, middleware, integration, hook, component, generated API client, runtime config, or test target changes.
- Skip Final Gate validators only when API/security/test surface is provably untouched.
- Skip `frontflow:validate-a11y` only when DOM/accessibility surface is untouched.
